# 自主巡航与避障 · 迭代规划

> 状态：🔵 待评审（已按**纯视觉路线**修订） | 最后更新：2026-10-07
> 方案依据：[自主巡航与避障方案.md](自主巡航与避障方案.md) ｜ 需求：R00049
> 路线图映射：T046（S0）、T042（S1–S3、S5）、T045-B（S4、S6）

> **本次修订要点**：TOF 尚未实现 → 主路线改为**纯视觉（经典 CV）**。
> 因此 **S2 不再需要采购硬件，全流程无硬件阻塞**；TOF 降级为可选增强。
> 代价是速度上限更低、暗光不可用，验收标准相应改写。

---

## 一、总体节奏

```
S0 基础能力 ──► S1 安全底座 ──► S2 纯视觉感知层 ──► S3 半自动避障 ──► S4 全自动巡航
（无硬件依赖）   （无硬件依赖）    （无硬件依赖）        （无硬件依赖）      （无硬件依赖）
                                        │
                                        └──► S5 语义增强（依赖 S2-P 预研结果）
                                                     │
                                                     ▼
                                              S6 场景化落地

S2-P 推理运行时预研（可选、可并行）──► 决定 S5 能做到什么程度
```

**关键变化**：**全流程不再被硬件采购阻塞**。原"硬件决策门"从阻塞项变为**并行决策项**。

**排序原则**

1. **安全先于功能**：S1 必须先于任何自主运动（S3/S4）
2. **纯视觉先做"能用"的（V1/V2），再谈"更好"的（V4）** —— V4 需要先打通推理运行时
3. **速度换安全**：纯视觉方案以更低的 `max_speed` 换取测距精度不足
4. **看不见 = 有障碍**：所有感知不确定一律倾向于停车（fail-safe）

## 二、每个迭代的完成定义（DoD）

- [ ] CI 通过：`ruff check` / `ruff format --check` / `mypy` / `pytest`
- [ ] **保持 Python 3.7 语法兼容**（真机 3.7.5；ruff `target-version=py37` 会拦）
- [ ] 核心逻辑有单元测试（硬件/相机依赖用 mock 挡掉）
- [ ] **真机验证通过**（不是只跑单测）
- [ ] **记录实测 CPU 占用增量**（CPU 已 70%，任何新模块都要报账）
- [ ] 涉及安全的行为变更，记录进方案文档或 `AGENT.md`
- [ ] 部署后跑一次 `scripts/healthcheck.sh`

## S0 · 基础能力：里程计 + IMU + 模式协议

**目标**：让机器人"知道自己在哪、动得多快"，并让模式切换**真正生效**（当前是空壳）。

| 交付物 | 说明 |
|---|---|
| `navigation/odometry.py` | 编码器 + IMU 融合 → `(x, y, θ, v, ω)`；麦轮运动学解算 |
| `navigation/mode_manager.py` | `manual/semi/auto` 状态机 + 接管规则（方案 §5） |
| 协议 | `control_mode_set/ack/status`、`odometry_status` |
| `collector.py` 扩展 | 上报 odom / imu（复用现有推送通道） |
| 前端 | 模式选择器**真正下发**；显示 `(x,y,θ)`、速度、模式与降级原因 |

**前置**：无 ｜ **硬件依赖**：无

**验收标准**

| # | 验收项 | 判据 |
|---|---|---|
| 1 | 模式切换真正生效 | 服务端收到并回 ack；前端状态与硬件行为一致 |
| 2 | 切回 manual 立即停车 | 下发到电机停止 **< 100ms** |
| 3 | 直线里程计精度 | 推直行 1m，误差 **< 20%** |
| 4 | 航向精度 | 原地 360°，陀螺融合航向误差 **< 15°** |
| 5 | 数据可见 | Web 端刷新 `(x,y,θ)`/IMU ≥ 5Hz |
| 6 | 编码器实测记录 | 分辨率、四轮一致性、方向约定写入文档 |

**不做**：避障、航线、任何自主运动（机器人**不会自己动**）

**风险**：R6 —— 编码器精度未知；若不足则退化为"仅陀螺航向 + 时间估距"，并如实记录。

**工作量**：1 迭代

## S1 · 安全底座（自主运动的前置条件）

**目标**：在让机器人"自己动"之前，先保证**任何异常都能停下**。

| 交付物 | 说明 |
|---|---|
| `navigation/safety.py` | S3–S7 兜底：看门狗、通信失联、低压、姿态异常、堵转 |
| 急停链路 | UI 一键急停 → 服务端 → `hardware.emergency_stop()` 全链路打通 |
| 模式安全前置 | `semi/auto` 默认禁用；开启需配置 + UI 二次确认 |
| 降级上报 | 安全层降级**必须广播原因**，禁止静默 |

**前置**：S0 ｜ **硬件依赖**：无

**验收标准**

| # | 触发方式 | 判据 |
|---|---|---|
| 1 | 杀掉决策协程 | ≤ **200ms** 停车并上报 |
| 2 | 拔网线（前端失联） | ≤ **200ms** 停车 |
| 3 | 按 UI 一键急停 | ≤ **200ms** 停车 |
| 4 | 注入低压 | 停车 + 广播低压原因 |
| 5 | 手抬一侧（倾斜） | 停车 + 广播姿态异常 |
| 6 | 手按住轮子（堵转） | 检测到并停车（或反转脱离） |
| 7 | 感知源不可用 | 按"有障碍"处理，停车 |

**工作量**：1 迭代

## S2 · 纯视觉感知层（**当前主路线，无硬件依赖**）

**目标**：用现有摄像头建立可用的障碍感知 —— 输出**风险扇区 / TTC / 可通行区域**。

| 交付物 | 说明 |
|---|---|
| `perception/base.py` | 感知源抽象：统一输出「风险扇区 + TTC + 可通行区域」；与将来 TOF 同构 |
| `perception/looming.py` | **V1**：稀疏光流（`calcOpticalFlowPyrLK`）+ **IMU 陀螺补偿旋转** → 发散度 → TTC |
| `perception/ground_plane.py` | **V2**：相机标定 → 地面单应 → 自由空间走廊 + 低矮障碍/落差 |
| `perception/active_scan.py` | **V3**：云台摆动产生运动视差 → 远近排序（补静止盲区） |
| `perception/calibration.py` | 内参标定 + 安装高度/俯仰参数（一次性，需实测填写） |
| 暗光/失效检测 | 亮度阈值 + 特征点数量 + 光流质量 → 判定感知是否可信 |
| `perception_status` + Web 可视化 | 风险扇区、TTC、可通行区域、感知可信度（便于调试与用户理解） |

**前置**：S1 ｜ **硬件依赖**：**无**（用现有 USB/CSI 摄像头 + 云台 + IMU）

**验收标准（按 TTC 而非距离考核）**

| # | 验收项 | 判据 |
|---|---|---|
| 1 | **V1 有效性** | 迎面障碍（人/墙/纸箱）：`TTC < 1.5s` 时**触发刹车**，重复 50 次**漏检 0** |
| 2 | **V1 抗旋转** | 原地旋转时不误触发（陀螺补偿生效）；误触发 **< 2 次 / 50 次** |
| 3 | **停车距离** | crawl 速度（0.1 m/s）下，从触发到停止的**行驶距离 < 15cm** |
| 4 | **V2 低矮障碍** | 桌沿/线缆/拖鞋等低矮障碍可判为不可通行；**纯白墙/玻璃不判为可通行**（保守停车） |
| 5 | **V3 静止可用性** | 静止状态下云台扫视可区分近处/远处障碍（给出远近排序） |
| 6 | **失效安全** | 遮挡镜头 / 关灯 / 盖住画面 → **判定为不可用并按有障碍停车** |
| 7 | **暗光禁止** | 亮度低于阈值时，**auto 模式被禁止**（或强制 crawl），并广播原因 |
| 8 | **算力报账** | 新增 CPU 占用 **≤ 20%**（单核口径）；视频帧率下降 **< 15%** |

**不做**：语义识别（人/宠物）、学习式深度、精确测距（这是它的原理局限）

**风险**：R2（暗光失效）、R4（无 TOF 兜底）、R7（旋转污染光流）、R5（算力）

**工作量**：2 迭代（经典 CV 调参耗时，尤其标定与阈值整定）

## S2-P · 推理运行时预研（**可选、可并行**）

**目标**：确认在本平台能否跑 GPU 推理 —— 它决定 S5 能做到什么程度。

| 调研项 | 要回答的问题 |
|---|---|
| TensorRT 系统绑定 | L4T R32.7 自带的 TRT 能否在 **Python 3.7 venv** 里导入？（系统包 vs venv 的 ABI 匹配） |
| onnxruntime-gpu | 是否有 aarch64 + py3.7 的可用轮子？ |
| OpenCV CUDA | 是否有必要重编译 OpenCV（耗时长、有风险）？或用 TRT 直接跑模型绕开 OpenCV DNN |
| 算力实测 | 小模型（如 MobileNet-SSD / 轻量检测器）在 Nano 上的**实测 FPS 与 CPU 占用** |

**交付物**：一份预研结论（可行 / 不可行 / 代价多大），据此决定 S5 是"上语义检测"还是"继续纯经典 CV"。

**为什么单列**：这是一次**技术风险不确定**的探索，不应混进功能迭代；且它**不阻塞** S2–S4。

**工作量**：0.5–1 迭代（spike）

## S3 · 半自动避障（人管方向，机管不撞）

**目标**：semi 模式下，人推着往障碍走时机器人**不撞**，且不劫持人的意图。

| 交付物 | 说明 |
|---|---|
| `navigation/avoidance.py` | 风险扇区 → "限速系数 + 横移绕行矢量"，叠加在人的输入之上 |
| 三档灵敏度 | 保守 / 标准 / 激进（可配置，UI 可选） |
| 速度上限约束 | semi/auto 下的硬上限（首版 ≤ **0.15–0.2 m/s**），与 manual 分离 |
| `avoidance_event` 上报 | 减速/绕行/急停的原因与时刻，前端可见 |
| 意图合成规则 | **只让开，不改前进方向**；绕行结束后恢复人的原始方向 |

**前置**：S0 + S2 ｜ **硬件依赖**：无

**验收标准**

| # | 验收项 | 判据 |
|---|---|---|
| 1 | 不撞墙 | 持续推向墙壁 → **不接触**，且保持安全距离（首版目标 ≥ 20cm） |
| 2 | 横移让开 | 前方障碍 + 侧向空间足够 → 横移绕过，不停死 |
| 3 | 意图不被劫持 | 绕行后恢复人的原始方向，不改变目的地 |
| 4 | 误刹率 | 正常开阔通行 100 次，误刹 **< 5%**（纯视觉放宽，优于"撞上"） |
| 5 | 通行走廊 | 70cm 宽通道可稳定通过（纯视觉留更大余量） |
| 6 | 事件可见 | 每次干预都有 `avoidance_event`，含原因与时序 |
| 7 | 暗光行为 | 暗光下 semi 仍可用（人控方向），但**限速到 crawl** 并提示 |

**不做**：自主选路（那是 S4）

**工作量**：1–2 迭代

## S4 · 全自动巡航（航线执行）

**目标**：auto 模式下按预设航线自主巡航并避障。

| 交付物 | 说明 |
|---|---|
| `navigation/planner.py` | 航点执行、到点判定、局部绕障、失败重试与放弃策略 |
| Web 航线编辑器 | 地图/列表形式增删航点、排序、命名；支持"以当前位置为航点" |
| `cruise_*` 协议 | start / pause / resume / stop + 状态回报 |
| 返航与停靠 | 一键返航（回起点）、到点后姿态对齐（可选） |
| **环境前置检查** | 起飞前检查亮度/感知可信度，**不满足则拒绝进入 auto** |
| 安全联动 | 巡航中触发反射层/降级 → **暂停巡航并上报**（不静默继续） |

**前置**：S1 + S3 ｜ **硬件依赖**：无

**验收标准**

| # | 验收项 | 判据 |
|---|---|---|
| 1 | 航线完成 | 设 3 个航点，能依次到达并回到起点；**终点误差 < 30cm** |
| 2 | 中途避障 | 航线中放障碍 → 绕行通过或安全停车等待，**不碰撞** |
| 3 | 控制操作 | 暂停/继续/停止 均正确，暂停后位置保持 |
| 4 | 单程距离 | 稳定完成 ≥ **5m** 单程巡航 |
| 5 | **环境门禁** | 暗光/感知不可用时**拒绝进入 auto** 并说明原因 |
| 6 | **必须有人在场** | 首版：auto 仅允许有人在场时启用（配置强制） |
| 7 | 降级可见 | 任何安全降级都会暂停巡航并上报原因 |

**不做**：跨房间、全局建图、长期全局定位、无人在场自主巡逻

**风险**：R1（里程计漂移）。若 5m 误差 > 30cm → 触发重新评估（加视觉路标校正或缩短航线）。

**工作量**：1–2 迭代

## S5 · 语义与视觉增强（**依赖 S2-P 结论**）

**目标**：在经典 CV 之上补语义能力（人/宠物避让）与更强的可通行性判断。

| 交付物 | 说明 |
|---|---|
| （视 S2-P 结论） | **可行** → TRT 小模型目标检测（人/宠物）；**不可行** → 退回经典 CV（Haar/HOG 人脸、颜色运动检测等），并降低承诺 |
| 与经典层融合 | 语义结果**仅作补充**，不参与安全兜底；置信度低时忽略 |
| 云台协同 | 巡航时小幅摆动扩大有效视野（可选） |

**前置**：S4（+ S2-P 结论）｜ **硬件依赖**：无

**验收标准**

| # | 验收项 | 判据 |
|---|---|---|
| 1 | 人员避让 | 视野内出现人 → 减速/绕开（**不依赖它做安全兜底**） |
| 2 | 不拖垮系统 | 开启后视频帧率下降 **< 20%**，控制延迟无明显劣化 |
| 3 | 误报控制 | 语义误报导致停车 < 5% |
| 4 | 降级 | 语义模块不可用时，系统退化为 S3/S4 能力且**不报错、不崩溃** |

**工作量**：1–2 迭代（强依赖 S2-P）

## 六、建议的启动方式

**从 S0 开始，理由是它把"未知数"提前暴露：**

- **不依赖任何采购或外部条件**，今天就能开工
- 交付即有用：Web 端能看到实时位姿，模式切换从空壳变真实
- 会**立刻暴露 R6（编码器精度）** 这个未知数 —— 如果里程计不可用，整个巡航方案要改
  （改为纯视觉航向 + 时间估距），**越早知道越好**
- 为 S1–S4 提供数据基础，不会白做

**S0 完成后建议紧接着做 S2 的 V1（光流/TTC）**：它是纯视觉路线的**技术风险最高点**，
应当尽早用真机验证"在这个平台上到底能不能可靠地算出 TTC"，再投入 S3/S4 的工程量。
