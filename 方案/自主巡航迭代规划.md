# 自主巡航与避障 · 迭代规划

> 状态：🔵 待评审 | 最后更新：2026-10-07
> 方案依据：[自主巡航与避障方案.md](自主巡航与避障方案.md) ｜ 需求：R00049
> 路线图映射：T046（S0）、T042（S1–S3、S5）、T045-B（S4、S6）

---

## 一、总体节奏

```
S0 基础能力 ──► S1 安全底座 ──► [硬件决策门] ──► S2 传感器 ──► S3 半自动避障
（无硬件依赖）    （无硬件依赖）                        │
                                                       ▼
                              S6 场景化 ◄── S5 视觉增强 ◄── S4 全自动巡航
```

**关键排序原则**

1. **S0/S1 不依赖任何新硬件**，先把"能定位、能安全停车、模式可控"做扎实
2. **S2 之前设一个硬件决策门** —— 测距传感器不到货，S2 之后的避障迭代无法验收
3. **安全先于功能**：S1 必须先于任何自主运动（S3/S4）
4. **视觉放最后**：算力最紧张、不确定性最高，且它是"补充"而非"兜底"

## 二、每个迭代的完成定义（DoD）

所有迭代共同遵守：

- [ ] 代码通过 CI：`ruff check` / `ruff format --check` / `mypy` / `pytest`
- [ ] **保持 Python 3.7 语法兼容**（真机 3.7.5；ruff `target-version=py37` 会拦）
- [ ] 新增单元测试覆盖核心逻辑（硬件依赖用 mock 挡掉）
- [ ] 真机验证通过（不是只跑单测）
- [ ] 涉及安全的行为变更，需在 `AGENT.md` 或方案文档中记录
- [ ] 部署后跑一次健康巡检（`scripts/healthcheck.sh`）

## S0 · 基础能力：里程计 + IMU + 模式协议

**目标**：让机器人"知道自己在哪、动得多快"，并让模式切换**真正生效**（当前是空壳）。

| 交付物 | 说明 |
|---|---|
| `navigation/odometry.py` | 编码器 + IMU 融合 → `(x, y, θ, v, ω)`；麦克纳姆轮运动学解算 |
| `navigation/mode_manager.py` | `manual/semi/auto` 状态机 + 接管规则（见方案 §5） |
| 协议 | `control_mode_set` / `control_mode_ack` / `control_mode_status`、`odometry_status` |
| `collector.py` 扩展 | 上报 odom / imu（复用现有推送通道） |
| 前端 | 模式选择器**真正下发**；显示 `(x,y,θ)`、速度、当前模式与降级原因 |

**前置**：无（可在当前真机直接开发）

**验收标准（可度量）**

| # | 验收项 | 判据 |
|---|---|---|
| 1 | 模式切换真正生效 | 服务端收到并回 ack；前端状态与硬件行为一致（不再只改本地 store） |
| 2 | 切回 manual 立即停车 | 从下发到电机停止 **< 100ms** |
| 3 | 直线里程计精度 | 人工推直行 1m，估计值误差 **< 20%** |
| 4 | 航向精度 | 原地旋转 360°，陀螺融合航向误差 **< 15°** |
| 5 | 数据可见 | Web 端实时刷新 `(x,y,θ)` 与 IMU，刷新 ≥ 5Hz |
| 6 | 编码器实测记录 | 记录分辨率、四轮一致性、正负方向约定（写入文档） |

**不做**：避障、航线、任何自主运动（本迭代机器人**不会自己动**）

**风险**：R6 —— Rosmaster 固件编码器精度未知。若精度不足，退化为"仅 IMU 航向 + 时间估距"，
并在 S0 验收中如实记录局限。

**工作量**：1 迭代

## S1 · 安全底座（自主运动的前置条件）

**目标**：在让机器人"自己动"之前，先保证**任何异常都能停下**。

| 交付物 | 说明 |
|---|---|
| `navigation/safety.py` | S3–S7 兜底：看门狗、通信失联、低压、姿态异常、堵转 |
| 急停链路 | UI 一键急停 → 服务端 → `hardware.emergency_stop()`，全链路打通 |
| 模式安全前置 | `semi/auto` 默认禁用；开启需配置 + UI 二次确认 |
| 降级上报 | 安全层降级必须广播原因，禁止静默 |

**前置**：S0（需要 odom/IMU 数据判断堵转与姿态）

**验收标准**

| # | 触发方式 | 判据 |
|---|---|---|
| 1 | 杀掉决策协程 | ≤ **200ms** 停车并上报 |
| 2 | 拔掉网线（前端失联） | ≤ **200ms** 停车 |
| 3 | 按 UI 一键急停 | ≤ **200ms** 停车 |
| 4 | 模拟低压（可注入阈值） | 停车 + 广播低压原因 |
| 5 | 倾斜超过阈值（手抬一侧） | 停车 + 广播姿态异常 |
| 6 | 堵转（手按住轮子） | 检测到并停车（或反转脱离） |
| 7 | 传感器读数异常注入 | 按"有障碍"处理（fail-safe），停车 |

**不做**：真实避障（此时还没有测距传感器）

**工作量**：1 迭代

## 🚦 硬件决策门（S2 开始前必须关闭）

| 决策项 | 选项 | 影响 |
|---|---|---|
| **D1 是否加装测距传感器** | (a) VL53L1X ×2–3（¥50–90，推荐）<br>(b) HC-SR04 ×2（¥10）<br>(c) 都不装 → 只做视觉 | 决定 S3/S4 能否按计划验收（只做视觉则避障等级下降，验收标准需放宽） |
| **D2 40-pin 上可用的 I2C/GPIO 引脚** | 物理确认（Rosmaster HAT 占用了排针） | 决定 TOF 接线方案；若不可用则走 HAT 扩展口或 USB-TOF |
| **D3 是否允许关闭桌面合成器 `compiz`** | 关 / 不关 | 关掉可回收 **70–80% CPU**，显著改善导航+视频共存 |

> 决策门未关闭时，可以继续做 S5 之外的**纯软件**工作（如航线编辑器 UI），但 **S3/S4 无法验收**。

## S2 · 测距传感器接入与反射层急停

**目标**：建立**不依赖视觉**的可靠近场测距与 L1 急停（安全兜底）。

| 交付物 | 说明 |
|---|---|
| `navigation/sensors/base.py` | 测距抽象：统一 `read() -> {方向: 距离_mm}`，可插拔 TOF / 超声 / 将来雷达 |
| `sensors/tof_vl53l1x.py` | I2C 驱动（含校准、异常值过滤、量程/超时处理） |
| 安装与标定 | 前 + 左/右 三向（或前二向后一）；记录安装偏差与盲区 |
| L1 反射层 | 独立高频协程，距离 < 阈值 → 直接刹车，**不经决策层** |
| `range_status` + Web 可视化 | 实时距离条/扇形图，便于调试与用户理解 |

**前置**：S1 完成 + **决策门 D1/D2 已关闭**

**验收标准**

| # | 验收项 | 判据 |
|---|---|---|
| 1 | 急停有效性 | 20cm 处放障碍，0.3m/s 前进 → **在 ≥10cm 处停住** |
| 2 | 稳定性 | 100 次重复接近测试：**漏检 0 次、误刹 0 次** |
| 3 | 失效安全 | 拔掉传感器 → 立即按"有障碍"停车 |
| 4 | 响应延迟 | 从测到危险到电机停 **< 50ms** |
| 5 | 覆盖方向 | 前向无盲区（记录侧向盲区范围） |
| 6 | 可视化 | Web 端距离刷新 ≥ 10Hz，与实际吻合（±2cm） |

**不做**：绕行（只做停，不绕）

**工作量**：1 迭代（含硬件到货与焊接/接线时间）

## S3 · 半自动避障（人管方向，机管不撞）

**目标**：semi 模式下，人推着往障碍走时机器人**不撞**，且不劫持人的意图。

| 交付物 | 说明 |
|---|---|
| `navigation/avoidance.py` | 扇区化 → 输出"限速系数 + 横移绕行矢量"，叠加在人的输入之上 |
| 三档灵敏度 | 保守 / 标准 / 激进（可配置，UI 可选） |
| `avoidance_event` 上报 | 减速/绕行/急停的原因与时刻，前端可见 |
| 与手动控制协同 | 明确"人的意图 vs 安全让开"的合成规则（**只让开，不改前进方向**） |

**前置**：S0 + S2

**验收标准**

| # | 验收项 | 判据 |
|---|---|---|
| 1 | 不撞墙 | 持续推向墙壁 → 保持 ≥ **15cm**，无接触 |
| 2 | 横移让开 | 前方障碍 + 侧向空间足够 → 横移绕过，不停死 |
| 3 | 意图不被劫持 | 绕行结束后，恢复人的原始方向（不改变目的地） |
| 4 | 误刹率 | 正常开阔通行 100 次，误刹 **< 2 次** |
| 5 | 通行走廊 | 60cm 宽通道可稳定通过 |
| 6 | 事件可见 | 每次干预都有 `avoidance_event`，含原因与时序 |

**不做**：自主选路（不会自己决定"往哪走"，那是 S4）

**工作量**：1 迭代

## S4 · 全自动巡航（航线执行）

**目标**：auto 模式下按预设航线自主巡航并避障。

| 交付物 | 说明 |
|---|---|
| `navigation/planner.py` | 航点执行、到点判定、局部绕障、失败重试与放弃策略 |
| Web 航线编辑器 | 地图/列表形式增删航点、排序、命名、保存；支持"以当前位置为航点" |
| `cruise_*` 协议 | start / pause / resume / stop + 状态回报 |
| 返航与停靠 | 一键返航（回起点）、到点后姿态对齐（可选） |
| 安全联动 | 巡航中触发 L1/降级 → 暂停巡航并上报（不静默继续） |

**前置**：S1 + S3（避障能力必须先可用）

**验收标准**

| # | 验收项 | 判据 |
|---|---|---|
| 1 | 航线完成 | 设 3 个航点，能依次到达并回到起点；**终点误差 < 30cm** |
| 2 | 中途避障 | 航线中放障碍 → 绕行通过或安全停车等待，**不碰撞** |
| 3 | 控制操作 | 暂停/继续/停止 均正确，暂停后位置保持 |
| 4 | 单程距离 | 稳定完成 ≥ **5m** 单程巡航（超出则需重新评估定位方案） |
| 5 | 降级可见 | 任何安全降级都会暂停巡航并上报原因 |
| 6 | 环境适应 | 常见家居地面（硬地板/短毛地毯）均可；长毛地毯/门槛**允许失败但必须上报** |

**不做**：跨房间、全局建图、长期全局定位（明确写在方案的非目标里）

**风险**：R1（里程计漂移）。若 5m 误差 > 30cm，触发**重新评估**：加视觉路标校正，
或降低承诺（缩短航线、增加人工校正点）。

**工作量**：1 迭代

## S5 · 视觉增强（GPU 层）

**目标**：补上测距传感器的盲区 —— 低矮、悬空、透明与远场障碍。

| 交付物 | 说明 |
|---|---|
| L4 视觉层 | 地面可通行区域估计（单应/视差）+ 低矮障碍检测 |
| TensorRT 推理 | 小模型跑 **GPU**（当前 GPU 0% 空闲），避免与 WebRTC 抢 CPU |
| 融合策略 | 视觉置信度低时不否决 TOF（视觉只做**补充**，不做安全兜底） |
| 云台协同 | 巡航时云台可微摆扩大视野（可选，增强但非必需） |

**前置**：S4（需在能自主运动的基础上叠加）

**验收标准**

| # | 验收项 | 判据 |
|---|---|---|
| 1 | 低矮障碍 | 桌沿/线缆/拖鞋等低矮障碍可识别并绕开（或停） |
| 2 | 透明/纯色 | 玻璃/白墙**不被判为可通行**（允许保守：停车而非误判通过） |
| 3 | 不拖垮系统 | 开启视觉后，视频帧率下降 < 20%，控制延迟无明显劣化 |
| 4 | 误报控制 | 视觉误报导致的停车 < 5%（避免"走两步停一次"） |
| 5 | 降级 | 视觉不可用时，系统退化为 S3/S4 能力且**不报错、不崩溃** |

**工作量**：1–2 迭代（视模型选型与 TRT 调优）

## S6 · 场景化落地

**目标**：把能力接到用户真正会用的场景。

| 交付物 | 说明 |
|---|---|
| 房间巡逻任务 | 命名航线 + 一键巡逻 + 完成后回起点 |
| 定时巡航 | 接 **T043** 定时任务系统（如每天固定时间巡逻一趟） |
| 异常上报 | 巡逻中检测到异常（障碍阻塞/被困）→ 上报截图/短视频 + 位置 |
| 场景联动接口 | 接 **T041**：场景事件（如"离家模式"）→ 触发巡逻 |
| 使用记录 | 巡航日志：起止时间、里程、干预次数、异常次数（Web 可查） |

**前置**：S4（+ S5 可选）

**验收标准**

| # | 验收项 | 判据 |
|---|---|---|
| 1 | 巡逻完成率 | 定时触发的巡逻任务完成率 ≥ **90%**（10 次实测） |
| 2 | 异常上报 | 人为制造阻塞 → 在 ≤ 10s 内上报，且 Web 端能看到证据 |
| 3 | 日志可用 | 每次巡航有完整记录（起止/里程/干预次数） |
| 4 | 与场景联动 | 至少打通 1 条场景触发链路（T041 或 T043） |

**工作量**：1 迭代

## 五、需要你决策的事项

| # | 事项 | 建议 | 阻塞什么 |
|---|---|---|---|
| 1 | **是否加装测距传感器**（¥50–90） | 装 2–3 个 VL53L1X | S2 及之后的全部避障迭代 |
| 2 | **40-pin 可用引脚确认**（物理查看） | 确认 I2C 引出位置 | TOF 接线方案 |
| 3 | **是否允许关闭桌面合成器**（回收 70–80% CPU） | 若机器人无需本地桌面则关掉 | 不影响功能，但显著影响导航+视频共存体验 |
| 4 | 巡航的使用场景与在场要求 | 明确"是否允许无人在场时自主巡航" | 决定速度上限与兜底策略的激进程度 |

## 六、建议的启动方式

**第一步只做 S0**，理由：

- 它**不依赖任何采购**，今天就能开工
- 它交付的是"能定位 + 模式真正可控"，**立刻可用**（Web 端能看到实时位姿）
- 它同时暴露 **R6（编码器精度）** 这个未知数 —— 早发现早调整路线
- 它为后续所有迭代提供数据基础，不会白做

S0 之后建议**先关掉硬件决策门**，再决定 S2 是按"加装传感器"还是"退化为纯视觉"推进。
