# 无陀螺仪条件下的纯视觉避障方案

> 前提：能力探测显示 **IMU 陀螺与加速度读数恒为 0**，且可能**根本没有该硬件**。
> 因此所有"靠航向"的设计（转向闭环、航线跟随、陀螺旋转补偿）都必须重做。

## 1. 失去 IMU 到底失去了什么

| 原来依赖 IMU 的能力 | 失去后的后果 |
|---|---|
| 航向估计（积分陀螺） | 不知道车头朝哪、转了多少度 |
| 转向闭环（转到目标角度） | 无法判断"转到位没有" |
| 旋转光流补偿 / 旋转门控 | 转动时无法区分"是我在转"还是"物体在靠近" |
| 倾角安全判据 | 无法检测跌落/被搬动 |

**结论：没有航向反馈，就不能做"转向某角度"这类控制。**
但注意 —— **避障本身并不需要航向**（只需要"哪个方向更空"），所以巡逻行为可以保住。

## 2. 三个可替代航向的来源（按可靠性）

### 替代①：视觉旋转估计（真正的"视觉陀螺"）
机体原地转动时，图像会产生**整体一致的流场**：
- 偏航（左右转）→ 近似**均匀水平平移**：`ω_y ≈ median(flow_x) / (f · dt)`
- 滚转 → 切向流
- 俯仰 → 近似均匀垂直平移

据此可**逐帧估计转动角速度并积分**得到相对转角。
改进做法（更稳）：不做逐帧积分，而是**与转动起始帧做特征匹配**，用单应矩阵/Horn 方法直接解出相对旋转 —— 无累积漂移。

- 优点：不需要任何额外硬件，纯视觉即可闭环
- 缺点：**弱纹理（白墙/地面）会失效**；快速转动会有运动模糊
- 适用：有纹理的室内环境

### 替代②：云台指令角（本机已有，最省事）
云台**能工作**（`set_pan` 已验证）。舵机是**可重复定位**的：
> 车体不动、只转云台时，**"我正在看哪个方向"= 我下发的 pan 角度**（相对车头）。

所以不需要 IMU 也能知道"我朝哪个方向看过、哪个方向更空"——
**云台本身就提供了方向基准**（车体朝向未知，但"相对车头的方向"是已知的）。
前提：舵机重复精度足够（需实测），且云台在运动中可以不被外力推动。

### 替代③：轮式编码器（待验证！）
麦克纳姆轮四轮编码器可解算出**转动分量**（与位移分量一起）。
- 若编码器**可用**：可得到较粗糙的转角（打滑会漂移，但短期可用于转向闭环）
- **优先要验证**：能力探测目前只查了 IMU，**没有查编码器**。
  今天里程计日志显示 `odometry_available=True` 且零偏标定"成功"（因为全 0 也算成功），
  但**编码器是否真的在计数尚未验证**。

## 3. 推荐的纯视觉架构（无 IMU）

```
方向感知：云台扫视（替代②）+ 视觉空旷度评估      ← 不依赖航向
障碍感知：V2 地面平面（低速首选，与速度无关）
          + V1 光流 TTC（行进中，需纹理与足够速度）
转向控制：视觉旋转估计（替代①）闭环
          └ 拿不到纹理时退化为"定时转动 + 保守角度"
位置/航向：不做（接受"无全局定位"）
```

**关键转变**：放弃"我要转到 90°"这类**绝对**控制，
改为"**我要转到这个方向看起来最空**"这类**相对/视觉伺服**控制 —— 后者不需要陀螺。

## 4. 具体到当前巡逻行为怎么改

1. **停止使用航向闭环**（IMU 死数据 → 现在的"转向无效"检测会一直触发，等于没转向）
2. 转向改为**视觉伺服**：
   - 转之前先记住当前画面（参考帧）
   - 转动过程中用流场估计已转过的角度
   - 达到目标角度（或转到"该方向空旷度够高"）即停
3. 观测方向一律**用云台 pan 角**表述（相对车头），不用绝对方位
4. 转向失败（无纹理）→ **不硬转**，改为"继续用云台扫视找一个不用大幅度转向的方向"

## 5. 诚实的天花板

1. **没有全局定位**：走远了一定回不来（无法知道"我在哪"）→ 只适合**局部巡逻**
2. **视觉旋转估计在弱纹理下失效**：走廊白墙、纯色地面、暗光都会失败
3. **兜底策略必须保守**：纹理不可靠时，靠"慢速 + 短段 + 频繁停下观察"来降低风险，
   而不是假设自己能精确转向
4. **运动模糊**：转动越快越糊，所以转向要**慢**（配合低转速）

## 6. 立即要做的三件事（按顺序）

1. **验证编码器是否活着**（可能直接白捡一个转角来源）—— 在能力探测里加编码器活性检查
2. **修正能力探测时机**：摄像头探测在启动时为 ✗（那时还没启流），需延迟探测
3. **实现视觉旋转估计**（替代①）：先离线验证可行性（用录制素材合成旋转），再上机
