## 0. 前置：健康巡检（已完成，FAIL=0）

```bash
scp wo-bot-control/scripts/healthcheck.sh trae@192.168.1.47:/tmp/
ssh trae@192.168.1.47 "SUDO_PASS='<密码>' bash /tmp/healthcheck.sh"
```

**预期**：`FAIL=0`，3 项 WARN（磁盘 90% / 非摄像头 L4T 包 / 2 个无害 NUL 元数据）。
若出现 FAIL，先处理再部署。

> 注意：不带 `SUDO_PASS` 时 apt 检查会显示"跳过"（WARN）——这是**正常**的，
> 不代表 apt 有问题（此误报已修复）。

## ⚠️ 配置陷阱（真实踩过）

`deploy.sh` 的流程是「备份 live `config/` → 解压仓库配置 → **还原 live 配置**」，
即 **live config 优先**。因此：

**在仓库 `config/config.yaml` 里新增/修改的配置，不会到达设备。**

症状：代码里读到的是 `{}`，一切回落到**代码默认值** —— 若默认值与预期一致，
问题会被完全掩盖（本项目就发生过：`navigation` 段从未到达设备，但因代码默认值
恰好等于配置值而无人察觉）。

**做法**：
- 改**设备**配置：直接编辑 `/opt/wobot/config/config.yaml`（改前备份）
- 改**默认值**（给新装设备用）：改仓库 `config/config.yaml`
- 改了设备配置后：`sudo systemctl restart wobot-control`，并在启动日志里**确认生效**
  （例：`Navigation S0 initialized: ... allow_semi=True, allow_auto=True`）

## 1. 部署

```bash
cd wo-bot-control
bash scripts/deploy.sh --sudo-password '<密码>' --host 192.168.1.47
```

- deploy.sh 会**先跑 healthcheck 预检**，再停止服务、同步代码（保留 `venv config data logs`）、
  备份 `config/` 与 `data/`、跑 DTLS 自测、重启服务
- 服务中断约 20 秒（浏览器画面会断开，刷新后恢复）

## 2. 部署后立即验证（不需要开自主模式，零风险）

| # | 验证项 | 操作 | 通过标准 |
|---|---|---|---|
| 1 | 服务健康 | `systemctl status wobot-control` | active，日志无 ERROR |
| 2 | 导航初始化 | 查日志 `Navigation S0 initialized` / `Safety S1 initialized` / `Perception S2 initialized` | 三行都在 |
| 3 | 里程计读数 | Web 端「控制模式」卡片 | 显示 pose；未标定时显示"（未标定·仅航向）" |
| 4 | **急停链路** | 点 UI 急停 | **≤200ms 停车**；出现红色横幅且原因是"用户一键急停"；**运动指令被拒** |
| 5 | 急停解除 | 点「解除急停」 | 横幅消失，可再次驱动 |
| 6 | 模式门禁 | 切 semi/auto | 被拒（`allow_semi/allow_auto=false`），提示明确 |
| 7 | 拔网线 | 断开浏览器/网络 | 安全停车触发（`link_lost`） |

## 3. 编码器标定（R6 未知数，里程计能否可用的关键）

1. 重置位姿原点（`odometry_reset`）
2. 让机器人**直行一段已知距离**（建议 ≥1m，地面平整）
3. 记录四轮编码器增量，`counts_per_meter = (Δm1+Δm2+Δm3+Δm4)/4 / 距离(m)`
4. 写入 `config.yaml → navigation.odometry.counts_per_meter`，重启服务

**验收**：直行 1m 后 `x ≈ 1.00 ± 0.15m`；原地转 90° 后 `θ ≈ 90° ± 10°`。

## 4. 视觉动态验证（S2 的真正验收，需要人配合）

在**受控场地**、有人在场、随时可急停的前提下：

1. 开启 `navigation.mode.allow_semi: true`，进入 semi
2. 由人拿纸箱/缓慢靠墙走向机器人
3. 记录触发时的 TTC 与停车距离

**通过标准**（见迭代规划 S2）：TTC 触发 < 1.5s；停车距离 < 15cm；
**旋转时不得误触发**；暗光下判定不可用而非硬算。

## 5. 回滚

```bash
# 部署前的版本仍在 git 中；deploy.sh 已备份 config/ 与 data/
cd wo-bot-control && git stash && bash scripts/deploy.sh --sudo-password '<密码>'
```
出现异常时的判据：服务反复重启、摄像头不可用、运动指令无响应。
